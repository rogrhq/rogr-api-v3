async def fetch_text(url: str, *, timeout: float = 10.0, headers: Optional[Dict[str, str]] = None) -> Dict[str, Any]:
    """
    Canonical async fetcher.
    Returns:
      {
        "text": <str>,                # empty when non-HTML or error
        "status": <int|str>,          # HTTP status or "error"
        "mime": <str|None>,           # e.g., "text/html; charset=utf-8"
        "final_url": <str|None>,      # after redirects
      }
    """
    h = {"User-Agent": _UA}
    if headers:
        h.update(headers)
    try:
        async with httpx.AsyncClient(follow_redirects=True, headers=h, timeout=timeout) as client:
            resp = await client.get(url)
            mime = resp.headers.get("content-type", "")
            final_url = str(resp.url) if resp.url else url
            text = ""
            if "text/html" in mime.lower():
                # Try response.text (decoded); fallback to bytes decode
                try:
                    text = resp.text
                except Exception:
                    text = resp.content.decode("utf-8", "ignore")
                text = _html_to_text(text)
            # For non-HTML (pdf, etc.), leave text empty; upstream decides handling later
            return {"text": text or "", "status": resp.status_code, "mime": mime, "final_url": final_url}
    except Exception as e:
        return {"text": "", "status": "error", "mime": None, "final_url": None}
----------------------------------------

================================================================================

KNOWN FACTS:
  - USDA.gov P23 score = 0.150 (semantic_read.py default for no content)
  - USDA.gov P24 score = 0.000 (no frames extracted)
  - USDA.gov authority = 0.858 (URL recognition worked)
  - Coverage = "snippet_only"

EVIDENCE CHAIN:

1. URL was identified correctly (authority score 0.858)
2. URL was passed to enrich_items_with_content()
3. fetch_text() was called via fetch_one()
4. One of these occurred:
   a) HTTP request failed (network, timeout, DNS)
   b) HTTP returned non-200 status
   c) Content-Type was not text/html
   d) Response was empty
   e) Exception occurred in fetch path

5. Result: content = "" was stored in fetch_cache
6. Item received content = ""
7. Coverage determined as "snippet_only"
8. P23 received empty content → defaulted to 0.150
9. P24 received empty content → no frames → 0.000

MOST LIKELY CAUSES FOR USDA.GOV:

HYPOTHESIS 1: Non-standard Content-Type
  - USDA.gov may return "text/html; charset=utf-8" but with parameters that don't match
  - fetch.py:46 checks: if "text/html" in mime.lower()
  - Should work for most variations
  - VERDICT: Unlikely

HYPOTHESIS 2: Redirect to authentication or error page
  - Government sites often require cookies, user agents, or have bot protection
  - httpx follows redirects (follow_redirects=True)
  - May land on error page that returns 200 but with empty/irrelevant content
  - VERDICT: Possible

HYPOTHESIS 3: Timeout
  - Default timeout: 10.0 seconds (fetch.py)
  - Government sites can be slow
  - Timeout → Exception → empty string
  - VERDICT: Possible

HYPOTHESIS 4: Bot detection / Rate limiting
  - User agent: "ROGRv2/preview-fetch (+https://example.local; contact: engineering@local)"
  - May be blocked by WAF or rate limiter
  - Would return 403, 429, or connection refused
  - All result in empty content
  - VERDICT: Likely

HYPOTHESIS 5: SSL/TLS verification issues
  - Government sites often have strict SSL requirements
  - httpx default behavior with SSL certificates
  - SSL error → Exception → empty string
  - VERDICT: Possible

HYPOTHESIS 6: JavaScript-required content
  - Modern sites require JS to render content
  - httpx/requests cannot execute JavaScript
  - HTML shell returned with no text content
  - _html_to_text() extracts nothing meaningful
  - VERDICT: Very Likely for ask.usda.gov (Salesforce Knowledge Base)

DIAGNOSIS: ask.usda.gov is a Salesforce Knowledge platform
  - URL pattern: /s/article/ is Salesforce Lightning
  - Likely requires JavaScript to render article content
  - Initial HTML has minimal text
  - Without JS execution, content appears empty
  - This explains:
      ✓ 200 OK response (page exists)
      ✓ HTML content-type (page is HTML)
      ✓ Empty text after _html_to_text() (JS-rendered content missing)
      ✓ No error logged (fetch technically succeeded)
